| Развёртывание | Статический хостинг | Node.js-сервер; VPS и домен подключаются позже |

### 0.2. Почему такой стек

- **Node.js + Fastify** — небольшой, быстрый и предсказуемый backend. Для публичного API и админ-панели достаточно одного процесса.
- **SQLite + `better-sqlite3`** — надёжное синхронное хранилище без отдельного сервера БД. Для 1 000 ответов и нескольких администраторов этого более чем достаточно.
- **WAL-режим SQLite** — параллельное чтение не блокируется записью; подходит для редких отправок и админ-просмотров.
- **Vanilla JS + Vite** — в проекте нет требований к React/Vue; для публичной формы и админ-панели фреймворк избыточен. Vite даёт dev-сервер, прокси и production-сборку.
- **Chart.js** — указан в исходном заказе; собирается локально, без CDN.
- **Серверные сессии вместо JWT** — токен можно отозвать сразу, а пароли и сессии не хранятся в браузере в открытом виде.

## 1. Контекст и цель

### 1.1. Бизнес-контекст

Заказчик проводит маркетинговое исследование и хочет собирать анонимные оценки партнёров по пяти параметрам. Респонденты получают публичную ссылку, проходят короткий опрос со своих устройств, а ответы попадают в единую базу. Администраторы видят сводную статистику и могут выгрузить данные.

Исходный заказ предполагал `localStorage`, но такой вариант не решает задачу сбора ответов с разных устройств. Версия 2.0 сохраняет исходную анкету и графики, но переносит хранение и аналитику на сервер.

### 1.2. Цель проекта

Дать инструмент, который:

1. Проводит респондента через короткий опрос без регистрации и без сбора персональных данных.
2. Принимает ответ с любого устройства по публичной ссылке.
3. Хранит все ответы централизованно и не теряет их при перезагрузке браузера.
4. Показывает администраторам средние оценки, распределение по возрастам и таблицу ответов.
5. Позволяет нескольким администраторам работать с одними данными.
6. Позволяет выгрузить ответы в CSV и безопасно удалить данные с подтверждением.

### 1.3. Учебная цель

Отработать полный цикл: ТЗ → архитектура → база данных → API → аутентификация → публичная форма → админ-панель → тестирование → документация → подготовка к развёртыванию.

## 3. Роли и сценарии

### 3.1. Роли

| Роль | Описание | Права |
|---|---|---|
| Респондент | Человек, который оценивает партнёра | Открыть публичную ссылку, пройти опрос, отправить ответ |
| Администратор | Доверенное лицо заказчика | Войти, видеть все ответы и статистику, фильтровать, экспортировать, удалять ответы, управлять администраторами |
| Система | Сервер и база | Валидирует, сохраняет, считает статистику, проверяет сессии |

Публичной регистрации нет. Первый администратор создаётся при запуске через переменные окружения или генерируется автоматически. Остальные администраторы добавляются из админ-панели.

### 3.2. Публичный сценарий

1. Администратор копирует публичную ссылку из админ-панели.
2. Респондент открывает ссылку на своём устройстве.
3. Нажимает «Начать опрос».
4. Выставляет 5 оценок, выбирает пол и возраст.
5. Нажимает «Отправить оценку».
6. Сервер проверяет данные и сохраняет ответ.
7. Респондент видит «Спасибо!» и может закрыть страницу.
8. Администратор обновляет обзор или ждёт автообновления и видит новый ответ в статистике.

### 3.3. Сценарий администратора

1. Открывает `/admin`.
2. Вводит логин и пароль.
3. Попадает на обзор: количество ответов, средний балл, последний ответ, карточки и графики.
4. Открывает «Ответы», задаёт фильтры по полу, возрасту и датам.
5. Выгружает CSV или очищает все ответы с подтверждением.
6. Открывает «Администраторы», создаёт новую учётную запись или отключает лишнюю.
7. Выходит из админки.

## 5. Функциональные требования

### 5.1. Маршруты и навигация

Публичная часть — SPA с hash-роутингом. Админка — отдельная HTML-страница `/admin` с hash-роутингом внутри.

| Маршрут | Экран | Доступ |
|---|---|---|
| `/#/` | Старт | Всегда |
| `/#/survey` | Опрос | Всегда |
| `/#/done` | Спасибо | Только после успешной отправки в текущей сессии |
| `/#/stats` | — | Редирект в `/admin` |
| `/admin` | Вход или обзор | Всегда; данные — после входа |
| `/admin#/overview` | Обзор | Только администратор |
| `/admin#/responses` | Ответы | Только администратор |
| `/admin#/admins` | Администраторы | Только администратор |
| Любой другой hash | — | Редирект на старт или обзор |

Правила:

- При смене экрана обновляется `document.title`.
- Фокус переносится на `h1` экрана.
- Скролл возвращается к началу страницы.
- При уходе с обзора графики уничтожаются.
- Прямой заход на `/#/done` без отправки перенаправляет на старт.
- Прямой заход в админку без сессии показывает форму входа.
- Старый публичный маршрут `/#/stats` перенаправляет в `/admin`, чтобы не оставлять публичную статистику.

### 5.2. Экран «Старт» (`/#/`)

**Назначение:** объяснить суть опроса, подчеркнуть анонимность и начать анкету.

**Состав:**

1. Заголовок «Оценка партнёра».
2. Подзаголовок «Анонимный опрос для маркетингового исследования».
3. Краткое описание: 5 качеств, шкала 1–10, 1–2 минуты.
4. Метки «5 качеств», «шкала 1–10», «1–2 минуты».
5. Блок анонимности: имя, контакты и IP не сохраняются; ответы доступны только администраторам.
6. Основная кнопка «Начать опрос» → `/#/survey`.
7. Ссылка «Вход для администратора» в шапке и футере.
8. Подпись «Результаты опроса не показываются участникам».

**Поведение:**

- Счётчик ответов на публичной странице не показывается.
- Публичной ссылки на статистику нет.
- Автоматических переходов нет.

**Критерии приёмки:**

- [ ] Все тексты на русском, без опечаток.
- [ ] «Начать опрос» ведёт на форму.
- [ ] Дисклеймер об анонимности виден на мобильном 360×640.
- [ ] Публичной статистики и счётчика ответов нет.

### 5.3. Экран «Опрос» (`/#/survey`)

#### 5.3.1. Пять оценок

Для каждого параметра выводится:

- название;
- короткая подсказка;
- слайдер `<input type="range" min="1" max="10" step="1" value="5">`;
- крупное числовое значение;
- подписи «1 — низкая» и «10 — высокая».

| Свойство | Значение |
|---|---|
| Диапазон | 1–10 |
| Шаг | 1 |
| Значение по умолчанию | 5 |
| Обязательность | Всегда валидно |
| Клавиатура | Стрелки, Home/End |
| Тач | Нативный слайдер, высота не меньше 44 px |
| Сброс после отправки | Возврат к 5 |

**Критерии приёмки:**

- [ ] 5 слайдеров с подписями.
- [ ] Число меняется синхронно.
- [ ] Стрелки меняют значение на 1.
- [ ] После успешной отправки форма сбрасывается.

#### 5.3.2. Пол и возраст

**Пол:** радиокнопки «М» и «Ж», обязательное поле, по умолчанию не выбрано.

**Возраст:** радиокнопки «до 25», «25–35», «старше 35», обязательное поле, по умолчанию не выбрано.

Обе группы имеют `fieldset`/`legend` или доступное имя группы. Случайный дефолт запрещён: он искажает аналитические разрезы.

#### 5.3.3. Валидация

Валидация выполняется при отправке, после первой ошибки — на `change`.

| Поле | Правило | Текст ошибки |
|---|---|---|
| Пол | `m` или `f` | «Выберите пол» |
| Возраст | `under25`, `25to35`, `over35` | «Выберите возраст» |
| Оценки | Целое 1–10 | «Оценка должна быть от 1 до 10» |

Поведение:

- Ошибка показывается под группой.
- Группа получает `aria-invalid` и `aria-describedby`.
- Фокус переходит к первой ошибке.
- Кнопка отправки не блокируется до получения ошибки.
- После исправления ошибка исчезает.
- Сервер повторно валидирует данные и возвращает 400 при нарушении.

#### 5.3.4. Отправка

1. Пользователь нажимает «Отправить оценку».
2. Клиентская валидация. При ошибке — фокус на первую.
3. Кнопка становится disabled, текст «Отправляем…».
4. `POST /api/responses` с JSON.
5. При 201 — переход на `/#/done`.
6. При 400 — сообщение сервера, кнопка снова активна.
7. При 429 — сообщение «Слишком много ответов с этого устройства. Подождите минуту».
8. При сетевой ошибке — сообщение о подключении, кнопка снова активна.
9. Повторный клик во время запроса не создаёт дубликат.

**Критерии приёмки:**

- [ ] Двойной клик не создаёт два ответа.
- [ ] При успехе в базе ровно одна новая запись.
- [ ] При ошибке пользователь видит понятное сообщение.
- [ ] После успеха форма чистая.

### 5.4. Экран «Спасибо» (`/#/done`)

**Состав:**

- Иконка успеха.
- Заголовок «Спасибо!».
- Текст: ответ сохранён анонимно на сервере.
- Кнопка «На главную».
- Кнопка «Пройти ещё раз».
- Напоминание: имя, контакты и IP не сохранялись.

**Поведение:**

- Экран доступен только после успешной отправки в текущей сессии.
- Флаг успеха хранится в памяти приложения, не в `localStorage`.
- После перезагрузки прямой заход на `/#/done` перенаправляет на старт.

### 5.5. Вход администратора (`/admin`)

**Состав:**

- Заголовок «Вход в админку».
- Поля «Логин» и «Пароль».
- Кнопка «Войти».
- Ошибка «Неверный логин или пароль» без раскрытия, существует ли учётная запись.
- Ссылка «Вернуться на сайт».
- Пометка «Публичной регистрации нет».

**Поведение:**

- Успешный вход устанавливает cookie сессии.
- Сессия действует 8 часов.
- После входа открывается обзор.
- При истёкшей сессии админка показывает форму входа.
- Выход удаляет серверную сессию и cookie.
- Rate limit: 10 попыток входа в минуту с одного IP.

**Критерии приёмки:**

- [ ] Неверный пароль не даёт доступ.
- [ ] Успешный вход открывает обзор.
- [ ] Cookie `HttpOnly` и `SameSite=Strict`.
- [ ] Выход завершает сессию.
- [ ] Публичной регистрации нет.

### 5.6. Обзор (`/admin#/overview`)

**Состав:**

- Заголовок «Обзор».
- Кнопки «Обновить» и «Экспорт CSV».
- Блок «Ссылка для участников» с readonly-полем и кнопкой «Копировать».
- Показатели: количество ответов, средний балл, последний ответ.
- Плашка «Пока мало ответов (N)» при 0 < N < 5.
- Пять карточек средних значений.
- График средних по параметрам.
- Гистограмма распределения по возрасту.
- Сворачиваемые таблицы данных под графиками.
- Подпись «Обновлено: … · автообновление каждые 30 секунд».

**Поведение:**

- Данные загружаются из `GET /api/admin/stats`.
- При N = 0 показывается пустое состояние и ссылка «Открыть опрос».
- Автообновление раз в 30 секунд, когда вкладка активна.
- При ошибке — блок с кнопкой «Повторить».
- Графики уничтожаются перед повторным созданием.
- Ссылка для участников формируется как `window.location.origin + '/'`.

**Критерии приёмки:**

- [ ] N совпадает с количеством ответов в базе.
- [ ] Средние совпадают с ручным расчётом.
- [ ] Графики строятся при N ≥ 1.
- [ ] При N = 0 нет ошибок и пустых canvas.
- [ ] Автообновление не создаёт дубликаты графиков.
- [ ] Ссылка копируется.

### 5.7. Ответы (`/admin#/responses`)

**Фильтры:**

- Пол: все, мужской, женский.
- Возраст: все, до 25, 25–35, старше 35.
- Дата «с» и «по» (включительно, границы дня в UTC).
- Кнопки «Применить» и «Сбросить».

**Таблица:**

| Колонка | Содержимое |
|---|---|
| Дата и время | Локальное время, `ДД.ММ.ГГГГ, ЧЧ:ММ` |
| Пол | М / Ж |
| Возраст | до 25 / 25–35 / старше 35 |
| Уверенность | 1–10 |
| Чувствительность | 1–10 |
| Инициативность | 1–10 |
| Адаптивность | 1–10 |
| Общее впечатление | 1–10 |
| Средний балл | Среднее пяти оценок |

**Поведение:**

- Пагинация по 50 записей.
- Сводка «Найдено N ответов · показаны X–Y».
- Пустое состояние при отсутствии результатов.
- «Экспорт CSV» учитывает текущие фильтры.
- «Очистить все» удаляет все ответы, включая скрытые фильтрами, после модального подтверждения.
- После удаления показывается toast с количеством.

**Критерии приёмки:**

- [ ] Фильтры работают по отдельности и вместе.
- [ ] Пагинация не теряет фильтры.
- [ ] CSV содержит те же строки, что и фильтр.
- [ ] Удаление требует подтверждения.
- [ ] После удаления N = 0.

### 5.8. Администраторы (`/admin#/admins`)

**Состав:**

- Форма «Добавить администратора»: логин, пароль, кнопка.
- Таблица: логин, статус, дата создания, последний вход, действия.
- Действия: «Пароль», «Отключить» / «Включить».

**Правила:**

- Логин: 3–32 символа, латиница, цифры, точка, дефис, подчёркивание.
- Логин приводится к нижнему регистру.
- Пароль: 8–200 символов.
- Все администраторы равноправны.
- Нельзя отключить собственную учётную запись.
- Нельзя отключить последнего активного администратора.
- Отключение завершает все сессии этого администратора.
- Смена пароля завершает остальные сессии; текущая сессия самого администратора сохраняется.
- Пароль хранится только в виде scrypt-хэша.
- Пароль после создания показывается только в форме создания; администратор должен передать его безопасно.

**Критерии приёмки:**

- [ ] Новый администратор может войти.
- [ ] Дубликат логина отклоняется с 409.
- [ ] Отключённый администратор не входит.
- [ ] Отключение завершает его сессии.
- [ ] Нельзя отключить себя.
- [ ] Нельзя отключить последнего активного.

### 5.9. Публичная ссылка

- Респонденты открывают главную страницу `/`.
- Ссылка не содержит персональных токенов.
- Ссылку можно переслать в мессенджере.
- Строгого ограничения «один ответ с устройства» нет.
- Повторные отправки ограничиваются rate limit: 20 ответов в минуту с одного IP.
- IP не сохраняется в базе, используется только в памяти rate limiter.

### 5.10. Приватность и доступ к данным

- Публичный API не отдаёт ответы, статистику или список администраторов.
- Все данные доступны только после входа.
- CSV и удаление защищены той же сессией.
- В публичной части нет имени, контактов, IP, комментариев.
- Нет сторонней аналитики, CDN и внешних шрифтов.
- Chart.js собирается в локальный бандл.
- `localStorage` больше не является источником истины.

### 5.11. Состояния интерфейса

| Состояние | Где | Что показываем |
|---|---|---|
| Пусто | Обзор, N=0 | Заглушка + «Открыть опрос» |
| Мало данных | Обзор, 0<N<5 | Инфо-плашка |
| Ошибка валидации | Опрос | Inline-ошибки + фокус |
| Отправка | Опрос | Кнопка disabled, «Отправляем…» |
| Успех | Спасибо | Галочка и действия |
| Ошибка сети | Опрос | Сообщение и повтор |
| 429 | Опрос / вход | Просьба подождать |
| Загрузка | Админка | Спиннер и текст |
| Ошибка API | Админка | Блок с кнопкой «Повторить» |
| Истёкшая сессия | Админка | Форма входа и toast |
| Нет результатов | Ответы | «Ничего не найдено» |
| Нет администраторов | Администраторы | Пустое состояние |

## 6. Данные

### 6.1. База данных

- СУБД: SQLite 3 через `better-sqlite3`.
- Файл по умолчанию: `data/tracker.sqlite`.
- Режим: WAL.
- Внешние ключи включены.
- `busy_timeout`: 5 секунд.
- Файлы `-wal` и `-shm` создаются автоматически.
- Каталог `data/` и файлы базы исключены из git.
- Переменная `DB_FILE` позволяет указать другой путь.

### 6.2. Таблица `admins`

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | UUID администратора |
| `login` | TEXT | NOT NULL, UNIQUE, COLLATE NOCASE | Логин |
| `password_hash` | TEXT | NOT NULL | scrypt-хэш |
| `is_active` | INTEGER | NOT NULL, CHECK 0/1 | Доступ |
| `created_at` | TEXT | NOT NULL | ISO 8601 UTC |
| `last_login_at` | TEXT | NULL | Последний успешный вход |

### 6.3. Таблица `sessions`

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `token_hash` | TEXT | PRIMARY KEY | SHA-256 от токена |
| `admin_id` | TEXT | NOT NULL, FK → admins.id, ON DELETE CASCADE | Владелец |
| `created_at` | TEXT | NOT NULL | Начало сессии |
| `expires_at` | TEXT | NOT NULL | Конец сессии |

Индекс: `idx_sessions_admin_id`.

### 6.4. Таблица `responses`

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | UUID ответа |
| `created_at` | TEXT | NOT NULL | ISO 8601 UTC |
| `gender` | TEXT | NOT NULL, CHECK `m`/`f` | Пол |
| `age_group` | TEXT | NOT NULL, CHECK `under25`/`25to35`/`over35` | Возраст |
| `confidence` | INTEGER | NOT NULL, CHECK 1–10 | Оценка |
| `sensitivity` | INTEGER | NOT NULL, CHECK 1–10 | Оценка |
| `initiative` | INTEGER | NOT NULL, CHECK 1–10 | Оценка |
| `adaptability` | INTEGER | NOT NULL, CHECK 1–10 | Оценка |
| `overall` | INTEGER | NOT NULL, CHECK 1–10 | Оценка |

Индексы:

- `idx_responses_created_at` по `created_at DESC`.
- `idx_responses_age_group` по `age_group`.

### 6.5. Формат ответа в API

```json
{
  "id": "5f1c2a9e-6d7b-4c2a-9f3e-1a2b3c4d5e6f",
  "createdAt": "2026-11-14T10:15:30.000Z",
  "gender": "m",
  "ageGroup": "25to35",
  "scores": {
    "confidence": 7,
    "sensitivity": 5,
    "initiative": 8,
    "adaptability": 6,
    "overall": 7
  }
}
```

Правила:

- `id` генерируется сервером.
- `createdAt` генерируется сервером.
- Лишние поля клиента игнорируются.
- Все пять оценок обязательны.
- `gender` и `ageGroup` обязательны.
- Строки не содержат HTML и не выводятся через небезопасный `innerHTML`.

### 6.6. Объём и хранение

- Один ответ — примерно 150–250 байт в SQLite.
- 1 000 ответов — менее 1 МБ данных.
- SQLite и WAL с запасом выдерживают такой объём.
- Ответы хранятся до ручного удаления администратором.
- Автоматического срока хранения нет.
- Резервные копии создаются вручную командой `npm run backup`.

### 6.7. Отказ от `localStorage`

- В v2 `localStorage` не используется для ответов.
- Старые ключи `partner-eval:v1` и `partner-eval:meta` не читаются.
- Автоматический перенос старых локальных данных не предусмотрен.
- Это осознанное решение: ответы должны быть централизованными и доступными с разных устройств.

## 7. API

### 7.1. Общие правила

- База URL: `/api`.
- Формат: JSON, UTF-8.
- Аутентификация: cookie `tracker_session`.
- Ошибки: JSON `{ "error": "...", "message": "...", "fields": { ... } }`.
- Все административные методы требуют активную сессию.
- Для изменяющих запросов при наличии `Origin` проверяется, что он совпадает с хостом.
- Ответы API не кэшируются (`Cache-Control: no-store`).
- Rate limit работает в памяти процесса и сбрасывается при перезапуске.

### 7.2. Публичные методы

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/health` | Публичный | Проверка сервера |
| POST | `/api/responses` | Публичный, 20/мин | Сохранить ответ |

### 7.3. Аутентификация

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| POST | `/api/auth/login` | Публичный, 10/мин | Вход |
| POST | `/api/auth/logout` | Публичный | Выход |
| GET | `/api/auth/me` | Сессия | Текущий администратор |

### 7.4. Админ-данные

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/admin/stats` | Статистика |
| GET | `/api/admin/responses` | Список с фильтрами и пагинацией |
| GET | `/api/admin/export.csv` | CSV с фильтрами |
| DELETE | `/api/admin/responses` | Удалить все ответы |

### 7.5. Администраторы

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/admin/admins` | Список |
| POST | `/api/admin/admins` | Создать |
| PATCH | `/api/admin/admins/:id` | Включить/отключить или сменить пароль |

## 8. Архитектура и технические решения

### 8.1. Стек

| Компонент | Выбор |
|---|---|
| Runtime | Node.js 24 (проверено на 24.20.0) |
| Backend | Fastify 5 |
| Cookie | `@fastify/cookie` |
| Статика | `@fastify/static` |
| Rate limit | `@fastify/rate-limit` |
| БД | SQLite + `better-sqlite3` |
| Env | `dotenv` |
| Frontend | Vanilla JS, ES modules |
| Сборка | Vite 6 |
| Графики | Chart.js 4 |
| Тесты | Vitest 5 |
| Dev-запуск | `concurrently` |
| Стили | Чистый CSS, custom properties |

### 8.2. Топология разработки

```text
Браузер
  ├─ http://127.0.0.1:5173/        → Vite (публичная часть)
  ├─ http://127.0.0.1:5173/admin   → Vite → admin.html
  └─ http://127.0.0.1:5173/api/*   → proxy → Fastify :3001
```

- Vite слушает `127.0.0.1:5173`.
- Fastify слушает `127.0.0.1:3001`.
- Прокси `/api` направляет запросы на backend.
- Плагин Vite переписывает `/admin` на `/admin.html`.
- Cookie устанавливается через прокси и остаётся same-origin для браузера.

### 8.3. Топология production

```text
Интернет → reverse proxy (позже: nginx/Caddy, HTTPS)
         → Fastify :3001
            ├─ /api/*
            ├─ /admin
            └─ dist/ (index.html, admin.html, assets)
```

- `npm run build` собирает `dist/`.
- `npm start` запускает Fastify и раздаёт статику.
- В production включается `COOKIE_SECURE=1`.
- За доверенным reverse proxy включается `TRUST_PROXY=1`.
- VPS, домен и HTTPS подключаются отдельным этапом.

### 8.5. Аутентификация и безопасность

**Пароли:**

- scrypt, `N=16384`, `r=8`, `p=1`, длина ключа 64 байта.
- Соль 16 байт.
- Формат хранения: `scrypt$N$r$p$salt$hash`.
- Сравнение через `timingSafeEqual`.
- Пароль не логируется и не возвращается API.

**Сессии:**

- Токен 32 случайных байта, base64url.
- В базе хранится только SHA-256 от токена.
- Cookie `tracker_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, `Secure` при production.
- Срок жизни — 8 часов.
- Просроченные сессии удаляются при входе и проверке.
- Выход удаляет сессию.
- Отключение администратора удаляет все его сессии.

**Доступ:**

- Нет публичной регистрации.
- Все `/api/admin/*` и `/api/auth/me` защищены.
- Первый администратор создаётся только если таблица `admins` пуста.
- Логин и пароль первого администратора задаются через `INITIAL_ADMIN_LOGIN` и `INITIAL_ADMIN_PASSWORD`.
- Если пароль не задан, генерируется 16-символьный пароль и выводится в консоль один раз.

**Защита запросов:**

- Rate limit: 20 ответов в минуту, 10 попыток входа в минуту.
- Проверка Origin для POST/PATCH/PUT/DELETE, если браузер прислал Origin.
- Заголовки: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`.
- API: `Cache-Control: no-store`.
- Админка: `X-Robots-Tag: noindex, nofollow`, `robots.txt` запрещает `/admin` и `/api`.
- Отдельного CSRF-токена нет: используется `SameSite=Strict` + проверка Origin.

**Ограничения текущей модели:**

- Нет восстановления пароля по email.
- Нет 2FA.
- Нет ролей.
- Нет журнала действий.
- Rate limit не распределён между процессами.
- Строгая защита от повторных ответов не реализована.

### 8.6. Приватность

- Не собираются имя, телефон, email, комментарии.
- IP не сохраняется в базе.
- IP используется только в памяти rate limiter и не пишется в логи приложения.
- Нет сторонней аналитики, рекламных пикселей и CDN.
- Chart.js и все зависимости собираются локально.
- Публичный API не отдаёт аналитику.
- CSV доступен только администратору.
- Удаление ответов необратимо и требует подтверждения.

### 8.7. Производительность

- Публичная страница: лёгкий JS-бандл, Chart.js загружается только в админке.
- Первая загрузка публичной части — ориентир ≤ 150 КБ gzip.
- Админка с Chart.js — ориентир ≤ 250 КБ gzip.
- Статистика считается на сервере по всем ответам; при 1 000 ответов это быстрее 50 мс.
- Список ответов отдаётся страницами по 50.
- Графики уничтожаются при уходе с обзора.
- Автообновление раз в 30 секунд.

### 8.8. Браузеры

Поддерживаются последние две версии:

- Chrome / Edge (desktop + Android).
- Firefox.
- Safari (macOS + iOS).

Обязательная проверка: iOS Safari и Android Chrome.

### 8.9. Резервное копирование и восстановление

**Создать копию:**

```bash
npm run backup
```

Копия сохраняется в `backups/tracker-<дата>.sqlite`.

**Восстановить:**

1. Остановить сервер.
2. Заменить `data/tracker.sqlite` файлом копии.
3. Удалить `data/tracker.sqlite-wal` и `data/tracker.sqlite-shm`, если они остались от старой базы.
4. Запустить сервер.

**Важно:** не копировать файл базы при активной записи вручную. Использовать `npm run backup` или останавливать сервер.

### 8.10. Развёртывание (следующий этап)

1. Арендовать VPS с Node.js 20+.
2. Разместить проект, выполнить `npm ci` и `npm run build`.
3. Настроить `.env`: `HOST=0.0.0.0`, `PORT=3001`, `COOKIE_SECURE=1`, `TRUST_PROXY=1`.
4. Настроить nginx/Caddy как reverse proxy и HTTPS.
5. Настроить автозапуск через systemd или NSSM.
6. Настроить ежедневный `npm run backup` и хранение копий вне сервера.
7. Проверить вход, публичную ссылку и экспорт с внешнего устройства.

## 13. Риски и допущения

| ID | Риск | Влияние | Меры |
|---|---|---|---|
| R-1 | Публичную ссылку можно переслать и отправить несколько ответов | Среднее | Rate limit; в будущем — одноразовые ссылки |
| R-2 | Нет строгой идентификации респондента | Среднее | Осознанно: анонимность важнее; фиксируем ограничение |
| R-3 | SQLite привязан к одному серверу | Низкое при 1 000 ответов | WAL, backup; при росте — PostgreSQL |
| R-4 | Первый пароль показывается только один раз | Среднее | Вывод в консоль, CLI для смены, README |
| R-5 | Нет восстановления пароля по email | Среднее | CLI `admin:password`, доступ к серверу |
| R-6 | Нет ролей: любой администратор может удалить данные | Среднее | Добавлять только доверенных; в будущем — роли и аудит |
| R-7 | Rate limit в памяти сбрасывается при перезапуске | Низкое | Для 1 000 ответов достаточно; при необходимости — Redis |
| R-8 | IP используется rate limiter | Низкое | Не сохраняется и не логируется |
| R-9 | CSV с `;` может неверно открыться в некоторых локалях | Низкое | BOM и `;` выбраны для русского Excel; документировано |
| R-10 | `COOKIE_SECURE` забыли включить в production | Высокое | Проверка при развёртывании, README |
| R-11 | Reverse proxy не передаёт корректный IP | Низкое | `TRUST_PROXY=1` |
| R-12 | Резервные копии не автоматизированы | Среднее | `npm run backup`, следующий этап — cron |
| R-13 | Пользовательские формулировки параметров трактуются по-разному | Среднее | Короткие определения под слайдерами |
| R-14 | Chart.js увеличивает бандл админки | Низкое | Chart.js только в админке, tree-shaking |

### Допущения

- Заказчик принимает публичную ссылку как основной сценарий.
- Количество ответов не превышает 1 000.
- Администраторы — доверенные лица.
- VPS, домен и HTTPS подключаются после приёмки v2.
- Дизайн-макета нет: используется нейтральный UI по токенам.
- Русский язык — единственный.
- Бюджет и срок — ориентиры из архива.

## 15. Глоссарий

- **Партнёр** — человек, которого оценивают. Без имени и идентификации.
- **Ответ** — одна анкета.
- **Средний балл** — среднее арифметическое всех выставленных оценок.
- **Доля** — процент ответов в возрастной группе от общего числа.
- **Администратор** — учётная запись с доступом к данным.
- **Сессия** — серверная запись, связанная с cookie браузера.
- **Публичная ссылка** — адрес главной страницы для респондентов.
- **WAL** — режим журналирования SQLite, ускоряющий параллельные чтения.
- **Rate limit** — ограничение частоты запросов.

## Приложение A. Быстрый запуск

### Требования

- Node.js 20+ (проверено на 24.20.0).
- npm 10+.
- Windows, macOS или Linux.

### Установка

```bash
npm install
```

### Разработка

```bash
npm run dev
```

- Публичная часть: `http://127.0.0.1:5173/`.
- Админка: `http://127.0.0.1:5173/admin`.
- API: `http://127.0.0.1:3001/api/health`.

### Production

```bash
npm run build
npm start
```

- Публичная часть: `http://127.0.0.1:3001/`.
- Админка: `http://127.0.0.1:3001/admin`.

### Первый администратор

При первом запуске, если таблица `admins` пуста:

- логин берётся из `INITIAL_ADMIN_LOGIN` (по умолчанию `admin`);
- пароль берётся из `INITIAL_ADMIN_PASSWORD`;
- если пароль не задан, генерируется и выводится в консоль один раз.

Создать администратора вручную:

```bash
npm run admin:create -- manager
```

Сменить пароль:

```bash
npm run admin:password -- manager
```

### Резервная копия

```bash
npm run backup
```

### Тесты

```bash
npm test
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | Адрес сервера |
| `PORT` | `3001` | Порт API |
| `DB_FILE` | `data/tracker.sqlite` | Путь к базе |
| `INITIAL_ADMIN_LOGIN` | `admin` | Логин первого администратора |
| `INITIAL_ADMIN_PASSWORD` | генерируется | Пароль первого администратора |
| `COOKIE_SECURE` | `0` | Secure-cookie |
| `TRUST_PROXY` | `0` | Доверять reverse proxy |
| `LOG_LEVEL` | `warn` | Уровень логов Fastify |
| `BACKUP_DIR` | `backups` | Каталог резервных копий |
